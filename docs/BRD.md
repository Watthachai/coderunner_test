# BRD — Cafe Pre-order & Pick-up System

## 1. บทสรุปผู้บริหาร
ร้านกาแฟสไตล์คาเฟ่เกาหลีประสบปัญหาลูกค้าหนาแน่นและต้องต่อคิวนานในช่วงเวลาเร่งด่วน ทำให้เสียโอกาสในการขาย และพนักงานเกิดความสับสนในการจัดเตรียมออเดอร์ตามคิว ระบบนี้พัฒนาขึ้นในรูปแบบ Web Application (Mobile-First สำหรับลูกค้า และ Desktop/Tablet สำหรับพนักงาน) เพื่อช่วยให้ลูกค้าสามารถสั่งเครื่องดื่ม ล่วงหน้า ปรับแต่งเมนู ชำระเงินผ่านการแนบสลิป และติดตามสถานะได้เอง ส่วนพนักงานสามารถรับและจัดการออเดอร์ได้แบบเรียลไทม์ ซึ่งช่วยลดเวลาการรอหน้าร้านและเพิ่มประสิทธิภาพการทำงานของพนักงานอย่างเป็นระบบ

## 2. เป้าหมายธุรกิจและตัวชี้วัด
| เป้าหมาย | ตัวชี้วัด (วัดได้) |
|---|---|
| ลดเวลาการรอคิวรับเครื่องดื่มของลูกค้าหน้าร้าน | เวลาเฉลี่ยที่ลูกค้าใช้รอรับเครื่องดื่มหน้าร้านลดลงเหลือไม่เกิน 3 นาที (วัดจากเวลาที่พนักงานกด "พร้อมรับ" ถึงเวลาที่ลูกค้ามารับจริง) |
| เพิ่มความถูกต้องในการจัดเตรียมออเดอร์ | อัตราการทำเครื่องดื่มผิดพลาดหรือผิดสูตรการปรับแต่งลดลงเหลือ 0% (วัดจากสถิติการเคลมเครื่องดื่มของลูกค้าหน้าร้าน) |
| เพิ่มยอดขายต่อบิล (Average Order Value) | ยอดขายเฉลี่ยต่อบิล (AOV) เพิ่มขึ้น 15% ภายใน 3 เดือนหลังเริ่มใช้งานระบบ (จากการแนะนำท็อปปิ้งและระบบสมาชิกสะสมแต้ม) |

## 3. กลุ่มผู้ใช้
| ผู้ใช้ | บทบาท | ความถี่การใช้ |
|---|---|---|
| **ลูกค้า (Customer)** | สั่งเครื่องดื่ม, ปรับแต่งเมนู, เลือกท็อปปิ้ง, ชำระเงินโดยแนบสลิป, สะสมแต้ม และติดตามสถานะออเดอร์ผ่านมือถือ | ทุกครั้งที่ต้องการสั่งเครื่องดื่ม (Daily / Weekly) |
| **พนักงานร้าน (Staff)** | ตรวจสอบออเดอร์ที่เข้ามาใหม่, ตรวจสอบสลิปเงินโอน, กดยืนยันออเดอร์ และอัปเดตสถานะการชงเครื่องดื่ม | ตลอดเวลาทำการของร้าน (Real-time) |

## 4. ขอบเขต
**ทำในเวอร์ชันนี้:**
- หน้าจอสั่งซื้อเครื่องดื่มแบบ Mobile-First สำหรับลูกค้า
- ระบบปรับแต่งเมนูเครื่องดื่มละเอียด (ระดับความหวาน, ร้อน/เย็น/ปั่น, เพิ่มท็อปปิ้ง, เลือกประเภทนม)
- ระบบตะกร้าสินค้า คำนวณราคาสินค้า ค่าท็อปปิ้ง และส่วนลดสมาชิกอัตโนมัติ
- ระบบชำระเงินด้วยการสแกน QR Code และอัปโหลดรูปภาพสลิปเพื่อยืนยัน
- หน้าจอติดตามสถานะออเดอร์แบบเรียลไทม์สำหรับลูกค้า (รอคิว / กำลังทำ / พร้อมรับ)
- ระบบสมาชิกสะสมแต้มและคำนวณส่วนลดตามระดับสมาชิก
- หน้าจอ Dashboard จัดการออเดอร์แบบเรียลไทม์สำหรับพนักงาน (ตรวจสอบสลิป, ยืนยันออเดอร์, เปลี่ยนสถานะ)

**ไม่ทำในเวอร์ชันนี้:**
- ระบบตัดบัตรเครดิต/เดบิต หรือ e-Wallet อัตโนมัติ (ใช้การแนบสลิปโอนเงินเท่านั้น)
- ระบบจัดส่งเดลิเวอรี (เน้นเฉพาะรับหน้าร้าน Pick-up เท่านั้น)
- ระบบจัดการสต็อกวัตถุดิบหลังบ้านแบบละเอียด (Inventory Management)

## 5. ความต้องการเชิงฟังก์ชัน
| รหัส | ความต้องการ | ความสำคัญ (must/should) |
|---|---|---|
| F-01 | ลูกค้าสามารถเลือกเมนูเครื่องดื่มและปรับแต่ง (ความหวาน, อุณหภูมิ, ท็อปปิ้ง, นม) ได้ตามต้องการ | must |
| F-02 | ระบบตะกร้าสินค้าต้องคำนวณราคารวม ค่าตัวเลือกเสริม และหักส่วนลดสมาชิกได้อย่างถูกต้อง | must |
| F-03 | ลูกค้าสามารถดู QR Code บัญชีร้าน และอัปโหลดไฟล์ภาพสลิปเพื่อยืนยันการชำระเงินได้ | must |
| F-04 | ลูกค้าสามารถติดตามสถานะออเดอร์ของตนเองได้แบบเรียลไทม์ (รอคิว -> กำลังทำ -> พร้อมรับ) | must |
| F-05 | พนักงานสามารถดูรายการออเดอร์เข้าใหม่แบบเรียลไทม์ ตรวจสอบสลิป และกดยืนยันเพื่อเริ่มทำได้ | must |
| F-06 | พนักงานสามารถกดเปลี่ยนสถานะออเดอร์เป็น "พร้อมรับ" เพื่อแจ้งเตือนไปยังหน้าจอของลูกค้าได้ | must |
| F-07 | ระบบสมาชิกสามารถสะสมแต้มจากการสั่งซื้อ และแสดงส่วนลดตามระดับสมาชิกของลูกค้าได้ | should |

## 6. ข้อมูลหลักในระบบ
- **Product (เมนูเครื่องดื่ม):** ID, ชื่อเมนู (ไทย/อังกฤษ), ราคาเริ่มต้น, รูปภาพ, หมวดหมู่, สถานะสินค้า (พร้อมขาย/หมด)
- **Customization Option (ตัวเลือกปรับแต่ง):** ID, ประเภทตัวเลือก (ความหวาน / อุณหภูมิ / ท็อปปิ้ง / นม), ชื่อตัวเลือก, ราคาบวกเพิ่ม (เช่น นมโอ๊ต +15 บาท, ไข่มุก +10 บาท)
- **Customer (ข้อมูลลูกค้า/สมาชิก):** ID, ชื่อ, เบอร์โทรศัพท์, แต้มสะสมปัจจุบัน, ระดับสมาชิก (Silver / Gold)
- **Order (ออเดอร์):** ID, รหัสออเดอร์ (เช่น #001), ID ลูกค้า, รายการสินค้าและตัวเลือกที่ปรับแต่ง, ราคารวมสุทธิ, รูปภาพสลิปโอนเงิน, สถานะออเดอร์ (รอตรวจสอบ / กำลังชง / พร้อมรับ / สำเร็จ), เวลาที่สร้างออเดอร์

## 7. ทิศทางการออกแบบ (Design Direction)
- **สีหลัก:** สีชมพูพาสเทล (Pastel Pink #FFD1DC) และสีครีมละมุน (Cream #FFFDD0)
- **โทน/อารมณ์:** สดใส น่ารัก สไตล์คาเฟ่เกาหลี มินิมอล (Minimalist & Pastel) เป็นมิตรและใช้งานง่าย
- **ฟอนต์/แบรนด์อ้างอิง:** ใช้ฟอนต์ไม่มีหัวที่มีความโค้งมนและดูนุ่มนวล เช่น IBM Plex Sans Thai (ปรับแต่งน้ำหนักฟอนต์ให้อ่านง่ายและน่ารัก)

## 8. เกณฑ์การยอมรับ
- ลูกค้าสามารถเลือกเครื่องดื่ม ปรับแต่งตัวเลือก แนบภาพสลิป และส่งออเดอร์เข้าสู่ระบบได้สำเร็จ (ใช่/ไม่ใช่)
- ระบบคำนวณราคาสินค้า ค่าท็อปปิ้ง และส่วนลดสมาชิกได้อย่างถูกต้อง 100% (ใช่/ไม่ใช่)
- พนักงานเห็นออเดอร์เข้าทันที ตรวจสอบสลิป และกดเปลี่ยนสถานะออเดอร์ได้ (ใช่/ไม่ใช่)
- หน้าจอติดตามสถานะของลูกค้าอัปเดตตามที่พนักงานกดแบบเรียลไทม์โดยไม่ต้องกดรีเฟรชหน้าจอ (ใช่/ไม่ใช่)
