# BRD — ExpenseFlow

## 1. บทสรุปผู้บริหาร
Digitalvalue (องค์กรที่ปรึกษาและพัฒนา AI/Data ขนาด 10 คน) เผชิญปัญหาความล่าช้าในการจัดการค่าใช้จ่ายและเงินทดรองจ่าย เอกสารสูญหาย และผู้บริหารไม่เห็นภาพรวมการเงินแบบ Real-time ทำให้ควบคุมงบประมาณได้ยาก ระบบ **ExpenseFlow** จึงถูกพัฒนาขึ้นในรูปแบบแอปพลิเคชัน (Mobile & Desktop) เพื่อช่วยให้พนักงานสามารถบันทึกเคลมค่าใช้จ่ายพร้อมระบบ OCR สแกนใบเสร็จ และขอเงินทดรองจ่าย (Cash Advance) ได้อย่างรวดเร็ว มีระบบอนุมัติ 3 ขั้นตอนที่โปร่งใส พร้อม Dashboard วิเคราะห์ข้อมูลแบบ Real-time และระบบ Export ข้อมูลบัญชีเพื่อเชื่อมโยงข้อมูลข้ามระบบ (Data Integration) สร้างผลลัพธ์ทางธุรกิจที่แท้จริงและเป็น Case Study ที่สมบูรณ์แบบ

## 2. เป้าหมายธุรกิจและตัวชี้วัด
| เป้าหมาย | ตัวชี้วัด (วัดได้) |
|---|---|
| 1. ลดระยะเวลาดำเนินงานเอกสาร | ระยะเวลาเฉลี่ยตั้งแต่พนักงานส่งคำขอ (Claim/Advance) จนถึงบัญชีทำจ่ายสำเร็จ ลดลงเหลือไม่เกิน 2 วันทำการ |
| 2. ควบคุมและตรวจสอบเงินทดรองจ่าย | ยอดเงินทดรองจ่ายค้างเคลียร์ (Outstanding Cash Advance) แสดงผลแบบ Real-time 100% บน Dashboard และไม่มีรายการค้างเกิน 15 วัน |
| 3. บูรณาการข้อมูลและลดการทำงานซ้ำซ้อน | ฝ่ายบัญชีสามารถส่งออกข้อมูลค่าใช้จ่ายเป็นไฟล์ Excel/CSV ในฟอร์แมตมาตรฐานเพื่อนำไปอัปโหลดเข้า ERP ภายนอกได้โดยไม่ต้องคีย์ข้อมูลซ้ำ (Zero Double-Entry) |

## 3. กลุ่มผู้ใช้
| ผู้ใช้ | บทบาท | ความถี่การใช้ |
|---|---|---|
| **พนักงาน (Employee / Requester)** | สร้างคำขอเงินทดรองจ่าย (Cash Advance), บันทึกเคลมค่าใช้จ่าย (Expense Claim) พร้อมแนบรูปใบเสร็จและใช้งาน OCR | ใช้งานทุกครั้งที่มีค่าใช้จ่ายเกิดขึ้น (เฉลี่ย 2-3 ครั้ง/สัปดาห์) |
| **หัวหน้าแผนก (Department Head / Approver)** | ตรวจสอบ รายละเอียด และกดอนุมัติหรือปฏิเสธคำขอของพนักงานในแผนกตนเอง | ใช้งานสัปดาห์ละ 1-2 ครั้ง (หรือเมื่อได้รับการแจ้งเตือน) |
| **ฝ่ายบัญชี (Finance / Reviewer & Payer)** | ตรวจสอบเอกสารขั้นสุดท้าย, บันทึกการจ่ายเงิน/รับเงินคืน, และส่งออกข้อมูล (Export) ไปลงบัญชีภายนอก | ใช้งานสัปดาห์ละ 1-2 ครั้ง |

## 4. ขอบเขต
**ทำในเวอร์ชันนี้:**
- **ระบบเงินทดรองจ่าย (Cash Advance):** พนักงานขอเงินล่วงหน้า -> หัวหน้าอนุมัติ -> บัญชีจ่ายเงิน -> พนักงานกลับมาเคลียร์ยอดโดยอ้างอิงใบเคลมค่าใช้จ่ายเพื่อหักลบกลบหนี้
- **ระบบบันทึกเคลมค่าใช้จ่ายพร้อม OCR:** พนักงานอัปโหลดรูปใบเสร็จ ระบบ OCR สแกนดึงข้อมูลอัตโนมัติ 3 ฟิลด์ (วันที่, ยอดเงินรวม, ชื่อร้านค้า/Supplier) โดยพนักงานสามารถตรวจสอบและแก้ไขข้อมูลก่อนบันทึกได้
- **ระบบจัดหมวดหมู่และศูนย์ต้นทุน:** แยกค่าใช้จ่ายตามหมวดหมู่ (เช่น ค่าเดินทาง, ค่ารับรอง) และตามแผนก (Cost Center)
- **ระบบอนุมัติ 3 ขั้นตอน (3-Step Approval Workflow):** พนักงาน -> หัวหน้าแผนก -> ฝ่ายบัญชี
- **Dashboard สรุปยอดใช้จ่าย Real-time:** แสดงกราฟค่าใช้จ่ายแยกตามหมวดหมู่ แผนก และยอดเงินทดรองจ่ายที่ยังไม่ได้เคลียร์
- **ระบบส่งออกข้อมูลบัญชี (ERP Integration):** ปุ่มส่งออกข้อมูลค่าใช้จ่ายทั้งหมดเป็นไฟล์ Excel/CSV ตามฟอร์แมตมาตรฐาน
- **สกุลเงิน:** รองรับสกุลเงินบาท (THB) อย่างเดียวเท่านั้น

**ไม่ทำในเวอร์ชันนี้:**
- ไม่ทำระบบสแกน OCR แบบดึงรายละเอียดรายการสินค้าแยกแถว (Line Items) — ดึงเฉพาะยอดรวม วันที่ และร้านค้าเท่านั้น
- ไม่ทำระบบเชื่อมต่อ API แบบ Real-time กับโปรแกรมบัญชีภายนอก — ใช้การส่งออกไฟล์ Excel/CSV แทน
- ไม่ทำระบบโอนเงินอัตโนมัติผ่านธนาคาร (Bank API Integration) — การจ่ายเงินจริงและการคืนเงินทอนให้ทำนอกระบบ แล้วมาบันทึกสถานะในระบบนี้

## 5. ความต้องการเชิงฟังก์ชัน
| รหัส | ความต้องการ | ความสำคัญ (must/should) |
|---|---|---|
| **F-01** | พนักงานสามารถสร้าง ส่ง และดูสถานะใบขอเงินทดรองจ่าย (Cash Advance) และใบเบิกค่าใช้จ่าย (Expense Claim) ของตนเองได้ | must |
| **F-02** | ระบบรองรับการอัปโหลดรูปภาพใบเสร็จ และใช้ OCR ดึงข้อมูล วันที่, ยอดเงินรวม, และชื่อร้านค้า เพื่อกรอกฟอร์มให้อัตโนมัติ | must |
| **F-03** | ระบบต้องรันเลขที่เอกสารอัตโนมัติแยกประเภทชัดเจน คือ `ADV-2026-XXXXX` และ `EXP-2026-XXXXX` | must |
| **F-04** | ระบบต้องมี Workflow อนุมัติ 3 ขั้นตอน โดยเปลี่ยนสถานะเอกสารตามการดำเนินการ (Draft -> Pending Approval -> Approved -> Paid / Rejected) | must |
| **F-05** | หัวหน้าแผนกและฝ่ายบัญชีสามารถกรอกข้อความ "เหตุผลการปฏิเสธ" ได้เมื่อกดปฏิเสธ (Reject) เอกสาร | must |
| **F-06** | Dashboard สำหรับผู้บริหารและบัญชี แสดงยอดใช้จ่ายสะสม, กราฟสัดส่วนตามแผนก/หมวดหมู่ และยอดเงินทดรองจ่ายค้างเคลียร์แบบ Real-time | must |
| **F-07** | ฝ่ายบัญชีสามารถเลือกช่วงเวลาและกด Export ข้อมูลค่าใช้จ่ายทั้งหมดออกมาเป็นไฟล์ Excel/CSV ได้ | must |

## 6. ข้อมูลหลักในระบบ
- **ผู้ใช้งาน (User Master Data):** รหัสพนักงาน, ชื่อ-นามสกุล, แผนก, บทบาท (Employee/Approver/Finance), อีเมล
- **ใบขอเงินทดรองจ่าย (Cash Advance Document):**
  - เลขที่เอกสาร (`ADV-2026-XXXXX`), วันที่ขอ, ผู้ขอ, แผนก, ยอดเงินที่ขอ (THB), คำอธิบาย/วัตถุประสงค์, สถานะ, ผู้อนุมัติ, วันที่ทำจ่าย
- **ใบเบิกค่าใช้จ่าย (Expense Claim Document):**
  - เลขที่เอกสาร (`EXP-2026-XXXXX`), เลขที่ใบขอเงินทดรองจ่ายที่อ้างอิง (ถ้ามี), วันที่ใบเสร็จ, ยอดเงินรวม (THB), หมวดหมู่ค่าใช้จ่าย, แผนก, ชื่อร้านค้า (Supplier), วิธีการจ่ายเงิน, รูปภาพใบเสร็จ, คำอธิบายเพิ่มเติม, สถานะเอกสาร

## 7. ทิศทางการออกแบบ (Design Direction)
- **สีหลัก:** สีน้ำเงินคราม (Indigo `#4F46E5`) ตัดกับสีขาวและเทาอ่อน
- **โทน/อารมณ์:** สดใส คล่องตัว สไตล์สตาร์ทอัพ (Vibrant & Friendly) ใช้งานง่ายและแสดงผลได้ดีทั้งบน Mobile (สำหรับพนักงานถ่ายรูปใบเสร็จ) และ Desktop (สำหรับบัญชีและผู้บริหารดู Dashboard)

## 8. เกณฑ์การยอมรับ
- **ผ่าน** เมื่อพนักงานสามารถสร้างใบเบิกค่าใช้จ่ายโดยอัปโหลดรูปใบเสร็จ และระบบสามารถ OCR ดึงข้อมูล วันที่, ยอดเงิน, และชื่อร้านค้าแสดงบนฟอร์มได้ถูกต้อง (หรือแก้ไขเพิ่มเติมได้)
- **ผ่าน** เมื่อเอกสารสามารถไหลตามสถานะพนักงาน -> หัวหน้าแผนก -> บัญชี ได้อย่างถูกต้องตามสิทธิ์การเข้าถึงของแต่ละ Role
- **ผ่าน** เมื่อระบบสามารถคำนวณหักลบกลบหนี้ระหว่างใบขอเงินทดรองจ่าย (ADV) และใบเบิกค่าใช้จ่าย (EXP) ที่อ้างอิงกันได้อย่างถูกต้อง
- **ผ่าน** เมื่อ Dashboard แสดงผลกราฟและตัวเลขสรุปยอดใช้จ่ายอัปเดตทันทีเมื่อฝ่ายบัญชีเปลี่ยนสถานะเอกสารเป็น "Paid"
- **ผ่าน** เมื่อฝ่ายบัญชีสามารถดาวน์โหลดไฟล์ Excel/CSV ที่มีข้อมูลฟิลด์สำคัญครบถ้วนและนำไปเปิดใช้งานได้จริง
