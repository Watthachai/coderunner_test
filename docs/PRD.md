# PRD — Cafe Pre-order & Pick-up System

## 1. ภาพรวม
ระบบสั่งเครื่องดื่มล่วงหน้าและรับสินค้าที่ร้าน (Cafe Pre-order & Pick-up System) พัฒนาขึ้นเพื่อแก้ปัญหาการต่อคิวหน้าร้านของคาเฟ่สไตล์เกาหลี โดยออกแบบเป็น Web Application แบบ Mobile-First สำหรับลูกค้า และ Desktop/Tablet สำหรับพนักงาน ระบบนี้ช่วยให้ลูกค้าสั่งเครื่องดื่ม ปรับแต่งเมนู และชำระเงินโดยการแนบสลิปได้ด้วยตนเอง พร้อมระบบสมาชิกสะสมแต้ม และหน้าจอติดตามสถานะแบบเรียลไทม์ (อ้างอิง: docs/BRD.md)

|---|---|---|---|

| 3 | **Cart (Customer)** | แสดงรายการสินค้าที่เลือกไว้ในตะกร้า | - รายการสินค้าที่เลือกพร้อมรายละเอียดการปรับแต่งและราคาต่อแก้ว<br>- ปุ่มเพิ่ม/ลดจำนวน หรือลบสินค้าออกจากตะกร้า<br>- ส่วนแสดงราคารวมเบื้องต้น (Subtotal)<br>- ปุ่ม "ไปที่หน้าชำระเงิน" |
| 4 | **Checkout & Membership (Customer)** | หน้ากรอกเบอร์โทรศัพท์สมาชิกและแนบหลักฐานการโอนเงิน | - ช่องกรอกเบอร์โทรศัพท์เพื่อค้นหา/สมัครสมาชิก<br>- ส่วนแสดงข้อมูลสมาชิก (ระดับสมาชิก, แต้มสะสม, ส่วนลดที่จะได้รับ: Silver 5%, Gold 10%)<br>- ยอดรวมสุทธิหลังหักส่วนลด และแต้มที่จะได้รับจากออเดอร์นี้<br>- QR Code บัญชีธนาคารของร้านสำหรับโอนเงิน<br>- ปุ่มอัปโหลดรูปภาพสลิปโอนเงิน (บังคับอัปโหลด)<br>- ปุ่ม "ยืนยันการสั่งซื้อและชำระเงิน" |
| 5 | **Order Tracking (Customer)** | หน้าจอติดตามสถานะออเดอร์แบบเรียลไทม์ | - รหัสออเดอร์ (เช่น #001)<br>- แถบแสดงสถานะปัจจุบัน (รอตรวจสอบ -> กำลังชง -> พร้อมรับ -> สำเร็จ)<br>- รายการสินค้าในออเดอร์<br>- สัญญาณเสียงเตือนและการสั่น (ถ้าเปิดบนมือถือ) เมื่อสถานะเปลี่ยนเป็น "พร้อมรับ" |
| 6 | **Staff Dashboard (Staff)** | หน้าจอจัดการออเดอร์และเมนูสำหรับพนักงาน (Desktop/Tablet) | - รายการออเดอร์ที่เข้ามาใหม่ เรียงตามเวลา (Real-time Queue)<br>- กล่องแสดงรูปภาพสลิปโอนเงินเพื่อตรวจสอบด้วยตา<br>- ปุ่มควบคุมสถานะออเดอร์: "ยืนยันออเดอร์" (เปลี่ยนเป็นกำลังชง), "พร้อมรับ", "สำเร็จ"<br>- ปุ่ม "ยกเลิกออเดอร์" (สำหรับกรณีสลิปปลอม/ของหมด)<br>- แท็บ "จัดการเมนู": ปุ่มสำหรับกด เปิด/ปิด สถานะสินค้าหมด (Out of Stock) ของแต่ละเมนู |

## 4. ข้อมูลและฟิลด์

### 4.1 Product (เมนูเครื่องดื่ม)
- `id` (String, Primary Key): รหัสสินค้า เช่น `PROD-001`
- `name_th` (String, Required): ชื่อภาษาไทย เช่น "เอสเพรสโซ่เย็น"
- `name_en` (String, Required): ชื่อภาษาอังกฤษ เช่น "Iced Espresso"
- `base_price` (Number, Required): ราคาเริ่มต้น เช่น `60`
- `image_url` (String, Required): ลิงก์รูปภาพสินค้า
- `category` (String, Required): หมวดหมู่ เช่น `Coffee`, `Tea`, `Non-Coffee`
- `is_available` (Boolean, Required, Default: `true`): สถานะพร้อมขาย (`true` = พร้อมขาย, `false` = หมด)

### 4.2 Customization Option (ตัวเลือกปรับแต่ง)
- `id` (String, Primary Key): รหัสตัวเลือก เช่น `OPT-001`
- `type` (String, Required): ประเภทตัวเลือก ได้แก่ `temperature` (อุณหภูมิ), `sweetness` (ความหวาน), `milk` (ประเภทนม), `topping` (ท็อปปิ้ง)
- `name` (String, Required): ชื่อตัวเลือก เช่น "นมโอ๊ต", "ไข่มุก", "หวาน 50%"
- `extra_price` (Number, Required, Default: `0`): ราคาบวกเพิ่ม เช่น `15` (สำหรับนมโอ๊ต), `0` (สำหรับระดับความหวาน)

### 4.3 Customer (ข้อมูลสมาชิก)
- `id` (String, Primary Key): รหัสสมาชิก
- `phone` (String, Required, Unique): เบอร์โทรศัพท์ (ใช้เป็นคีย์หลักในการค้นหา) เช่น `0812345678`
- `points` (Number, Required, Default: `0`): แต้มสะสมปัจจุบัน
- `tier` (String, Required, Default: `General`): ระดับสมาชิก ได้แก่ `General` (ไม่มีส่วนลด), `Silver` (ส่วนลด 5%), `Gold` (ส่วนลด 10%)

### 4.4 Order (ออเดอร์)
- `id` (String, Primary Key): รหัสออเดอร์ระบบ
- `order_number` (String, Required): รหัสออเดอร์สำหรับเรียกขาน เช่น `#001` (รีเซ็ตทุกวัน)
- `phone` (String, Required): เบอร์โทรศัพท์ลูกค้าที่ใช้สั่งซื้อ
- `items` (Array of Objects, Required): รายการสินค้าที่สั่งซื้อ ประกอบด้วย:
  - `product_id` (String)
  - `product_name` (String)
  - `customizations` (Array of Strings เช่น `["เย็น", "หวาน 50%", "นมโอ๊ต", "ไข่มุก"]`)
  - `quantity` (Number)
  - `price_per_unit` (Number)
- `subtotal` (Number, Required): ราคารวมก่อนหักส่วนลด
- `discount_amount` (Number, Required, Default: `0`): จำนวนเงินส่วนลดสมาชิก
- `net_total` (Number, Required): ราคารวมสุทธิที่ต้องชำระ
- `points_earned` (Number, Required): แต้มที่ได้รับจากออเดอร์นี้ (`Floor(net_total / 10)`)
- `slip_image_url` (String, Required): ลิงก์รูปภาพสลิปโอนเงินที่ลูกค้าอัปโหลด
- `status` (String, Required, Default: `pending`): สถานะออเดอร์ ได้แก่ `pending` (รอตรวจสอบ), `preparing` (กำลังชง), `ready` (พร้อมรับ), `completed` (สำเร็จ), `cancelled` (ยกเลิก)
- `created_at` (Timestamp, Required): เวลาที่สร้างออเดอร์

## 5. Design Spec
- **ชุดสี (Color Palette):**
  - Primary Color: สีชมพูพาสเทล (Pastel Pink) `#FFD1DC` (ใช้เป็นสีปุ่มหลัก, แถบสถานะเด่น)
  - Secondary Color: สีครีมละมุน (Cream) `#FFFDD0` (ใช้เป็นสีพื้นหลังหลักของแอปพลิเคชัน)
  - Text Color: สีน้ำตาลเข้ม `#4A3B32` (เพื่อให้อ่านง่ายและเข้ากับโทนคาเฟ่)
  - Accent Color: สีเขียวพาสเทล `#C1E1C1` (ใช้แสดงสถานะ "พร้อมรับ" หรือปุ่มยืนยันของพนักงาน)
- **การจัดวาง (Layout):**
  - หน้าแสดงเมนูเครื่องดื่ม (Menu Listing) ต้องจัดวางแบบ **Grid (2 คอลัมน์บนมือถือ)** เน้นรูปภาพสินค้าขนาดใหญ่สไตล์เกาหลี มินิมอล มีขอบมน (Border Radius: `16px`) และเงาฟุ้งแบบนุ่มนวล (Soft Shadow)
- **ฟอนต์ (Typography):**
  - ใช้ฟอนต์ไม่มีหัวที่มีความโค้งมนและดูนุ่มนวล เช่น **IBM Plex Sans Thai** โดยกำหนดน้ำหนักฟอนต์ (Font Weight) ให้ชัดเจนสำหรับหัวข้อ (Bold) และเนื้อหา (Regular)

## 6. Non-functional
- **Mobile-First Design:** หน้าจอฝั่งลูกค้าทั้งหมดต้องได้รับการปรับแต่งให้ใช้งานบนสมาร์ทโฟนได้อย่างสมบูรณ์แบบ (Responsive Design รองรับขนาดหน้าจอตั้งแต่ 320px ขึ้นไป)
- **Real-time Status Sync:** การอัปเดตสถานะออเดอร์จากฝั่งพนักงานไปยังลูกค้าต้องใช้ระบบ Real-time (เช่น WebSockets, Server-Sent Events หรือ Long Polling ทุกๆ 5 วินาทีสำหรับระบบ Demo) โดยหน้าจอของลูกค้าต้องเปลี่ยนสถานะทันทีโดยไม่ต้องรีเฟรชหน้าจอ
- **Performance:** หน้าแรก (Menu Listing) ต้องโหลดและแสดงผลรูปภาพ Grid ทั้งหมดได้ภายในเวลาไม่เกิน 2 วินาที บนเครือข่าย 3G/4G ทั่วไป
- **Accessibility:** ขนาดตัวอักษรของชื่อเมนูและราคาต้องไม่ต่ำกว่า `14px` และมีอัตราส่วนคอนทราสต์ของสีตัวอักษรกับพื้นหลังที่อ่านง่าย

## 7. ขอบเขตของ demo (Out of Scope)
- **ไม่มีระบบตัดบัตรเครดิต/เดบิต หรือ e-Wallet อัตโนมัติ:** การชำระเงินจะจำลองผ่านการสแกน QR Code และให้ลูกค้าอัปโหลดรูปภาพสลิปเท่านั้น โดยพนักงานจะเป็นผู้ตรวจสอบความถูกต้องของยอดเงินและสลิปด้วยตาตนเอง (Manual Verification)
- **ไม่มีระบบจัดส่งเดลิเวอรี:** ระบบรองรับเฉพาะการสั่งล่วงหน้าและเดินมารับที่หน้าร้าน (Pick-up) เท่านั้น
- **ไม่มีระบบประวัติการสั่งซื้อย้อนหลัง (Order History):** ลูกค้าสั่งซื้อแบบ Guest ได้ทันที เมื่อปิดหน้าจอติดตามสถานะหรือออเดอร์เสร็จสิ้นกระบวนการ จะไม่สามารถกลับมาดูออเดอร์เดิมได้อีก เพื่อเน้นความรวดเร็วในการสั่งซื้อ (Fast Checkout)
- **ไม่มีระบบจัดการสต็อกวัตถุดิบหลังบ้านแบบละเอียด (Inventory Management):** มีเพียงปุ่มให้พนักงานกดเปิด/ปิดสถานะสินค้าหมด (Out of Stock) เป็นรายเมนูเท่านั้น
